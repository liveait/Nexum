# ADR 0007：HTTP 文件发布与任务完成对账

- 状态：已接受；已实现，验证见下文
- 日期：2026-10-11

## 背景

[ADR 0004](0004-cross-restart-http-resume.zh-CN.md) 能在不覆盖已有目标的前提下发布完整 HTTP 文件。文件发布和 SQLite 任务保存无法组成一个事务：进程可能在发布后、保存 `Completed` 前退出。原先恢复后的 worker 会把自己已下载的完整文件当作目标冲突。没有 validator 或已知总长度的响应同样存在此问题。[ADR 0006](0006-managed-macos-server.zh-CN.md) 要求解决此窗口后才能通过 M1。

## 决策

1. 响应通过长度校验、读取至 EOF 且暂存文件同步后，engine 在发布前原子写入有大小上限的 JSON 完成凭证。凭证保存在 Server 私有的 `data_dir/http-completions/`，以任务 ID 的 SHA-256 命名；绑定任务 ID、来源、规范化目标及暂存路径、实际字节数、原始可选总长度、文件身份和 SHA-256。既有 HTTP validator sidecar 保持独立；通用任务存储不新增 HTTP 字段。
2. 保留既有不覆盖目标的原子 rename 和 hard-link 回退。最终进度与 `Completed` 通过 Core 的一次 repository update 同时持久化成功后，才清理完成凭证。保存失败保留凭证供下次对账；绝不覆盖已有目标。
3. worker 在发 HTTP 请求前尝试凭证对账。目标是普通文件且身份、长度、摘要均匹配时，无需网络即可完成任务。目标不存在、完整暂存文件匹配时，可无需网络重新发布。仅摘要相同不能认领用户替换的文件。拒绝符号链接、特殊文件、损坏或超大的凭证以及绑定不符；保留冲突的用户文件并报告错误。
4. 启动只读取有上限的小型凭证元数据。具有正确绑定凭证的失败任务可重新排队对账；其他失败任务保持原恢复规则。摘要校验放在 Server 就绪后的 HTTP worker，配合暂停和取消。已经完成的任务只清理残留凭证，不重新读取文件摘要，避免超出托管 Server 六秒就绪预算。
5. 删除残留暂存路径前校验文件身份，包括 hard-link 回退后两个路径同时存在的情况。删除任务先停止 worker、删除数据库任务，再清理凭证。清理失败时报告错误，并将剩余私有凭证保留为孤儿证据；不会重新创建已删除的数据库任务。复用不存在的任务 ID 前必须成功清理孤儿凭证，避免旧任务证据误认新任务。清理不删除最终目标。

## 验证计划

使用隔离临时存储和本地 HTTP fixture，覆盖发布前已写凭证、发布后尚未保存完成、保存完成后尚未清理、无 validator 且未知长度、持久化失败后重启、任务 ID 复用、hard-link 回退、取消、内容或身份变化，以及损坏／符号链接／特殊文件凭证。核对准确字节和持久化状态，确认恢复不发第二次 HTTP 请求。不新增无条件暴露的生产崩溃注入入口，不操作运行中 Desktop 的任务数据库。

## 影响

- 进程崩溃后可让完整文件与任务状态收敛，无需重复下载，也不认领无关文件。
- 准备凭证和待对账恢复需要完整读取一次本地文件摘要；不得拖慢 Server 就绪。
- 本决策解决进程崩溃窗口。硬件掉电保障仍取决于平台和文件系统的同步语义；凭证不是下载字节的备份。
- M0 实际 VoiceOver 朗读以及 M1 全新用户／升级最终验收仍是独立门槛。本次后端变更不代表任一里程碑完成。

## 已实现验证

10 月 11 日的 engine 测试覆盖凭证准备与发布、强制 hard-link 回退、恢复修改时间后的摘要变化、相同内容但不同文件身份、空响应、绑定错误、超大／损坏记录、符号链接／FIFO 保护，以及暂停／取消。Core 测试证明最终进度、状态和事件同时提交，保存被拒绝时全部保持不变。

Server 测试使用真实子进程和独立临时数据库。本地 HTTP fixture 提供下载字节，SQLite trigger 拒绝完成保存，另有测试同时拒绝两个终态；随后终止子进程、用同一数据目录重启，核对完整文件和持久化 `Completed`。其他 fixture 重建发布前和持久化后边界，在 HTTP listener 已关闭后恢复未知长度响应，保留替换文件并拒绝不安全的任务 ID 复用。后端证据见[发布流程](../RELEASE.zh-CN.md#http-完成对账后端证据)。本切片未重启原生 App；Windows 文件身份已实现，但未在本机 macOS 验证中实际执行。

## 考虑过的替代方案

- **按大小或摘要接受任何已有文件**：可能误认用户创建的替换文件，无法证明由本任务发布。
- **先保存 `Completed` 再发布文件**：可能在最终文件不存在时报告成功。
- **给每个持久化任务增加 HTTP 字段**：改变通用存储契约，也无法让文件系统和 SQLite 提交原子化。
- **监听前校验所有凭证的文件摘要**：大文件拖慢托管启动，可能反复触发 supervisor 超时。
