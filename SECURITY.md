# 安全策略 / Security Policy

Nexum 重视安全问题。

Nexum takes security issues seriously.

<a id="reporting-a-vulnerability"></a>
<a id="报告安全漏洞"></a>

## 报告安全漏洞 / Reporting a Vulnerability

如果发现可能影响用户、数据或系统安全的漏洞，请不要直接在公开 Issue 中披露完整细节。

Do not disclose complete details of a vulnerability affecting users, data, or systems in a public Issue.

请通过 GitHub Security Advisories（如果仓库已启用）或项目维护者提供的适当私下联系方式报告。

Use GitHub Security Advisories when enabled, or contact the maintainers through an appropriate private channel.

报告中尽量包含 / Please include when available:

- 受影响的版本或提交 / Affected version or commit
- 漏洞类型 / Vulnerability type
- 复现步骤 / Reproduction steps
- 影响范围 / Impact
- 可能的修复建议 / Suggested mitigation

<a id="handling"></a>
<a id="处理原则"></a>

## 处理原则 / Handling

维护者会确认报告、评估影响，并在适当情况下协调修复及确定合适的公开披露时间。

Maintainers will acknowledge the report, assess its impact, coordinate remediation when appropriate, and determine a suitable disclosure timeline.

在漏洞得到修复前，请避免公开能够直接利用该漏洞的细节。

Avoid publishing directly exploitable details before a vulnerability is fixed.
